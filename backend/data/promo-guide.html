certshack — SEO Review

Generated 2026-05-07. Issues ordered by impact. Items marked DONE were fixed in this session.

Critical — blocking indexing

  1. DONE CRITICAL Generic meta description overrides page-specific description on every exam/lab page.
    The base index.html contained a fallback <meta name="description"> that appeared before the page-specific one injected by generate-static-meta.mjs. Google uses whichever tag appears first, so every exam and lab page showed the generic fallback in search results.
    Fixed: scripts/generate-static-meta.mjs — strip fallback before injecting page meta. index.html fallback also updated to "IT certifications".
  2. DONE CRITICAL 32 pages flagged "Alternate page with proper canonical tag" in Search Console.
    CloudFront was serving root index.html (canonical = homepage) for all unknown paths. Fixed in two parts: (1) CloudFront now serves 404.html (with noindex) for error paths instead of index.html; (2) a CloudFront Function rewrites clean paths (e.g. /exams/AI-901 → /exams/AI-901/index.html) so pre-built static files are served directly from S3 with their correct canonicals.
    Fixed: infra/terraform/modules/cloudfront/viewer-request.js + main.tf, scripts/generate-static-meta.mjs (404.html)
  3. CRITICAL AI-901 (and likely other recently added exams) unknown to Google — not in any crawled page.
    URL Inspection shows "URL is unknown to Google" with "No referring sitemaps detected" and "No referring page." The sitemap was last read 4/30/26. Any exam added after that date is invisible until Google re-crawls the sitemap or finds an internal link. With no crawlable internal links from /exams (it's a JS-rendered SPA), new exams have no discovery path.
    Fix (short-term): Use "Request Indexing" in URL Inspection for each new exam. Fix (long-term): Static /exams and /skill-labs listing pages — see item 5.
    Search Console → URL Inspection → https://certshack.com/exams/AI-901
  4. CRITICAL 16 pages "Crawled — currently not indexed."
    Google crawled these pages but chose not to index them, most likely because the crawled HTML was thin (body = <div id="root"></div> with no visible text). This affects any page that doesn't yet have a pre-rendered static file. Google's JS rendering is a second-wave process and lower priority — pages without real HTML content on first parse are deprioritised or dropped.
    Fix: Ensure all sitemap URLs have pre-built static HTML with body content before deployment. The listing pages generated in this session (items 5 and 6) address the most important cases.
    Search Console → Indexing → Pages → "Crawled - currently not indexed" (16 pages)

High — hurting rankings

  1. DONE HIGH No static HTML for /exams listing page — Google can't follow links to exam detail pages.
    The /exams route is a React SPA page with no pre-rendered body content. Googlebot's first-pass crawl sees no <a href> links to individual exam pages. All exam page discovery depends entirely on the sitemap. A static listing page with real links passes authority and makes discovery resilient.
    Fixed: scripts/generate-static-meta.mjs — generates dist/exams/index.html with H1, 15 linked exam entries, and full meta tags.
  2. DONE HIGH No static HTML for /skill-labs listing page.
    Same issue as above. 216 skill labs are discoverable only via the sitemap. A static listing page with all 216 labs linked provides a reliable crawl path and signals the breadth of content.
    Fixed: scripts/generate-static-meta.mjs — generates dist/skill-labs/index.html with H1, 216 linked lab entries, and full meta tags.
  3. DONE HIGH Missing <PageMeta> on /exams and /skill-labs listing pages — no runtime Helmet tags.
    Already handled by ExamApp.tsx which calls <PageMeta route={route}> for all routes. Both practice and skill-labs have entries in the META object. No additional changes needed.
    src/exam/ExamApp.tsx:159, src/components/PageMeta.tsx
  4. DONE — partially HIGH /pricing has H2 as top-level heading instead of H1.
    /exams and /skill-labs both have correct H1s rendered by the shared ExamApp header (ExamApp.tsx:330). However the pricing page uses <h2> where an <h1> should be — it sits outside the shared header and doesn't benefit from that pattern.
    Fix: Change <h2> → <h1> on PricingPage line 316.
    src/pricing/PricingPage.tsx:316
  5. DONE HIGH No dedicated 404 page — invalid URLs return 200 with homepage content (soft 404).
    NotFoundPage component created with noindex, nofollow Helmet tag. Unknown paths now map to 'not-found' route in ExamContext (previously fell through to 'home'). CloudFront serves 404.html for error paths; the CloudFront Function ensures valid pre-built paths are served directly.
    Fixed: src/components/NotFoundPage.tsx, src/exam/ExamContext.tsx, src/exam/ExamApp.tsx, src/exam/types.ts

Medium — improving rankings and click-through

  1. DONE MEDIUM Exam detail page titles follow a weak pattern for search intent.
    Current pattern: certshack | Microsoft Azure AI Fundamentals (AI-901) Practice Exam. Leading with the brand name pushes the exam code and keywords to the right where they're truncated in SERPs (~60 char limit). Users searching "AI-901 practice exam" scan the left side of the title first.
    Suggested pattern: AI-901 Practice Exam | certshack — exam code first, brand last. This also aligns with how competitors title their pages.
    scripts/generate-static-meta.mjs:80, src/components/PageMeta.tsx:170
  2. DONE MEDIUM Skill lab pages lack keywords in their descriptions.
    The generated description for lab pages is: "[lab.description]. Interactive [platform] skill lab. [difficulty] difficulty. Covers [tech]." This buries the certification relevance. Users search for "AWS SAA-C03 practice lab" or "CompTIA hands-on lab" — those phrases don't appear.
    Fix: Append related exam codes to the description and keywords. The lab JSON has a relatedExamCodes field — use it: "...Covers CloudFront, S3, IAM. Relevant to SAA-C03."
    scripts/generate-static-meta.mjs:117-118
  3. DONE MEDIUM Homepage static HTML has no page-specific meta — relies entirely on runtime Helmet.
    dist/index.html (served for the root / route) has only the generic fallback title ("certshack") and generic description. The homepage Helmet tags (FAQPage schema, WebSite schema, rich description) are injected at runtime by React. For Google's first-pass crawl of the homepage, it may see no meaningful meta.
    Fix: Add the homepage to generate-static-meta.mjs so dist/index.html gets a proper title, description, canonical, and JSON-LD baked in.
    scripts/generate-static-meta.mjs, frontend/dist/index.html
  4. DONE MEDIUM No breadcrumb structured data (BreadcrumbList schema).
    Breadcrumbs appear in Google search results as path indicators (e.g. certshack › Exams › AI-901) and can increase click-through rate. Neither the static meta generator nor the React components emit BreadcrumbList JSON-LD.
    Fix: Add BreadcrumbList to exam detail and skill lab detail pages in generate-static-meta.mjs:
    Home → Practice Exams → [Exam Name] and Home → Skill Labs → [Lab Name]
    scripts/generate-static-meta.mjs
  5. DONE MEDIUM 8 internal routes have no PageMeta entries and will show generic title/description.
    Routes with no metadata: exam-setup, exam-attempt-review, diagrams, feedback, basket, metrics. Some of these (diagrams, basket) should probably be noindex since they're not useful search landing pages. exam-attempt-review could have a meaningful title.
    Fix: Add entries to the META object in PageMeta.tsx — noindex: true for utility pages, descriptive titles for content pages.
    src/components/PageMeta.tsx
